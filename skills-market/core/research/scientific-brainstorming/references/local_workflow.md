# Project recording and execution handoff

Use for an ongoing project or a requested saved session. Reuse relevant local
instructions, project records, and established authorization; inspect artifacts
when a recap’s current-state claims matter. Do not rerun an analysis merely to
refresh an ideation note.

For a brief chat brainstorm, the response is sufficient. For a saved session,
reuse the existing log/note convention. A single dated Markdown note is enough
unless structured exchange makes a JSON register useful. Follow project language
choices; the optional project-manager skill provides its own continuity defaults.
Do not create parallel trackers or duplicate narratives.

Record only applicable fields:

- focal question, scope, constraints, and information already seen;
- candidate IDs, origins, assumptions, predictions, and disconfirming observations;
- actual evidence checks, queries/dates, contrary evidence, and search limits;
- qualitative tradeoffs, or requested scores/weights/uncertainty and sensitivity;
- actual reviewer or labeled self-critique, unresolved dissent, and limitations;
- recommendation versus actual researcher decision, rationale, and next action.

Preserve meaningful revisions and decision provenance. Do not fabricate a human
contributor, approval, date, or completed stage to fill a template. The optional
CLI scaffold contains pending stages, not governance findings; use its documented
`ai-assisted` origin and record model identity only when actually known.

Keep the index for stable navigation. Update an existing recap when the project
requires it; installing a skill does not authorize edits to unrelated projects.
Keep private project context local unless disclosure is part of the request.

A recommendation alone does not authorize new data selection, models, thresholds,
splits, parameter sweeps, substantial compute, or replacing canonical results.
Existing authorization still carries forward. When execution is requested, infer
its scientific boundary using the project’s workflow or
`scientific-coding-governance` if available. Preserve unexpected valid results;
do not tune them away. Ideas generated after seeing outcomes are exploratory;
confirmatory testing needs new data or a genuinely untouched holdout with the
relevant decisions fixed before its outcomes are seen.
