# Scientific implementation and result preservation

Use the sections relevant to the action. These controls preserve scientific
meaning and existing evidence; they do not require repeated approval for work
the researcher already requested.

## Scope and authority

Scientific choices include cohorts, inclusion/filtering, normalization, models,
tests, covariates, thresholds, metrics, splits, biological groupings, and contrasts.
Expose consequential package defaults. Resolve a missing choice when it changes
the result; otherwise reuse the approved configuration.

Method-preserving implementation includes vectorization, local helpers, plotting
mechanics, and equivalent execution strategies. Carry it out inside the requested
resource/interface boundary. Discuss an environment, public-interface, or major
architecture change when it expands that boundary or creates a material impact;
the fact that code is reversible does not select a scientific method.

For autonomous exploration, establish the objective, adjustable choices, data,
evaluation basis, resource limit, and stopping condition from the request. Ask
for genuinely missing scientific boundaries before dependent exploration.
Simple factual inspection needs no new exploration contract.

## Data, outputs, and execution

Keep raw data immutable. Preserve meaningful exploratory results and their
provenance. An authorized deterministic rerun may replace its reproducible output;
give notice when overwriting it. If existing results may be wrong, follow the
result-impacting debugging sequence below before changing canonical status.

Preserve unrelated user changes. Use the user's Git workflow and existing
environment, scheduler allocation, and resource policy. A requested upload or
publication supplies its own scope; the skill does not add permission to disclose
private research context or perform adjacent external actions.

Record the consequential parameters, relevant seed, input identifier, code state
or entry point, and output path in the project's existing format. Do not add an
experiment tracker solely to satisfy this policy.

## Verification and anomalies

Check the failure modes that could invalidate the agreed analysis: cell/sample
identifier alignment, condition labels, matrix provenance, expected groups,
replication, contrast direction, and the method's actual input assumptions.
Add a small assertion when it represents an approved invariant; do not transform
data in order to make it pass.

For an anomaly threatening data, method, or evaluation validity:

1. Preserve the affected artifacts and determine their provenance.
2. Diagnose from existing outputs, logs, configuration, code, and relevant sources.
3. Explain the proposed fix and any scientific decision it changes. Reuse prior
   authorization when it covers that fix; otherwise resolve the decision first.
4. Produce a corrected result separately when the old result may have influenced
   interpretation; compare both and obtain the researcher's canonical choice.

Do not clip, drop, renormalize, substitute a method, suppress a failed test, or
tune parameters merely to hide the anomaly. A technically valid unexpected result
remains a result: complete the agreed analysis and report it without opportunistic
adaptation. Mechanical errors that have not affected results can be fixed directly.

## Interpretation and stopping

Internal evidence supports observations about the current data. Biological,
mechanistic, or out-of-sample claims need appropriate external grounding. Primary
studies, method documentation, and authoritative databases can contextualize or
challenge a result; they do not retroactively validate it. Seek contrary as well
as supportive evidence when interpreting a claim.

Separate observation, interpretation, hypothesis, and conclusion. State unresolved
conflicts rather than imposing a false consensus. Stop at the agreed output;
broader refactors, benchmarks, compatibility layers, and new follow-up experiments
need their own concrete purpose and scope. Requested review or hardening remains
in scope; do not dismiss an actual reachable failure as hypothetical over-defense.
